This issue already absorbed HPA-1036; do not open a second ticket/PR for its Gallery work. This is a plan, not a claim that the bug is reproduced or fixed.

## User outcomes

1. **Tray pieces:** normal and rotated pieces remain recognizable with tabs but their **140% masked-image envelope** does not overlap neighboring slots. The selected 2×2 inspection area stays deliberately larger; placed board pieces, full-size click/drag targets, image-status indicators and filters remain intact.
2. **Responsive reload:** an untouched tray follows the current viewport, so *load at 1100px → resize to 1440px* has the same **settled** tray/board geometry as *load fresh at 1440px*. A user-dragged/keyboard-resized tray is a session-local override and **intentionally resets to the responsive default on reload**; it is not persisted.
3. **Gallery settle:** initial request spinner disappears when its current request settles; the card grid and initial spinner are mutually exclusive today. Pagination's `load-more-spinner` (which **can** appear with cards) disappears after current-page success/error/abort; superseded requests never corrupt current results. If controlled regressions pass before changes, classify historical spinner report as not reproduced rather than rewriting working logic.
4. **Discoverability:** category names visibly accompany existing icons when the Gallery header can accommodate them; compact radios preserve their **already-implemented accessible names**. Puzzle card titles use a consistent two-line clamp across widths (plus existing full-title `title`), so narrow touch users can read more than an ellipsis without obscuring statuses/actions.

## Existing code and decisions

### Tray and board

- `apps/web/src/lib/components/PuzzleInventoryPanel.svelte` owns the scrollable `.pieces-grid` and square `.piece-slot` elements. Selected `.piece-slot.selected-expanded` spans 2×2 tracks, intentionally increasing inspection size. Keep filtering, scroll and keyboard roving intact; do not add paging.
- `apps/web/src/lib/components/PuzzlePiece.svelte` is **only used by the inventory**, not placed-board cells. Its image is `EXPANSION_FACTOR = 1.4` times the visual wrapper and offset by `TAB_RATIO`; jigsaw tab tips reach the mask canvas boundary (`packages/types/src/jigsaw-path.ts`). Therefore the **wrapper bounds are a safe geometric upper bound**, not a harmless empty rectangle to disregard. Rotation is quarter-turn on a square visual, so one 90° case covers the same axis-aligned envelope as 180°/270°.
- Use **one proportional inset for the visual surface**, not fixed gaps/padding that fail for different slot sizes. For a 140% canvas the minimum inset on each axis without hover is `(1 - 1/1.4)/2 ≈ 14.29%` of the slot (equivalent to `TAB_RATIO/EXPANSION_FACTOR`); preserving the existing `hover:scale-105` requires `(1 - 1/(1.4*1.05))/2 ≈ 15.99%`. Prefer around **16%** if hover remains; alternatively remove hover enlargement and use the smaller inset. Let a browser-mode `getBoundingClientRect` containment regression choose the actual rule. Apply to ordinary **and selected** tray visual areas relative to their respective slot bounds, without shrinking the interactive slot/button or clipping tabs. The 100%-slot image-status decoration must remain legible.
- Scroll clipping already prevents piece art from painting over the inventory header on the present CSS; verify that top-row tabs are **not clipped at the scroll edge** after the inset. Preserve the selected 2×2 inspection, visual highlight and hint behavior. No second preview or placed-piece change.
- `apps/web/src/routes/puzzle/[id]/+page.svelte` currently initializes `requestedTrayWidth` **once** inside `loadPuzzle()`; `handleWindowResize()` updates viewport measurements but not that requested width. This explains the resize→reload shift without any `ResizeObserver` failure. Replace the one-time default with an explicit **session-only override** (`manualTrayWidth: number | null`), derive `requestedTrayWidth = manualTrayWidth ?? getDefaultPuzzleTrayWidth(puzzle, {width: viewportWidth, height: viewportHeight})`, and retain existing `appliedTrayWidth` clamp and `getResponsivePuzzleBoardMetrics` as the single layout authorities. Clear the manual override on new puzzle load; reload naturally starts without it. No persisted preference, migration or new layout service.
- Targeted regression: desktop 1100→1440 resize on an **untouched tray**, wait for fonts/ResizeObserver to settle, record board viewport, tray CSS width and slot bounds, reload **at 1440** and compare within ~2px. Manual separator resize resetting to default on reload is intended and should be documented/tested with the existing desktop tray interaction. The compact tray below 1024px already uses CSS fluid sizing; no redundant 390px reload geometry E2E is required.

### Gallery

- `apps/web/src/routes/+page.svelte` has mutually exclusive `{#if loading}` / card branches. The spinner visible **with** populated cards can only be `load-more-spinner`, not `loading-state`. Existing `queryVersion`, abort guards and current-request `.finally()` should remain; do not create a request framework or change image loading. The full lifecycle suite is **`apps/web/src/routes/page.svelte.test.ts`** (not the short `page.svelte.spec.ts` smoke suite) and already covers empty/error, stale next-page responses, aborted next-page, retry and IntersectionObserver guards.
- Add just two missing focused unit scenarios: a table-driven check that **both** request spinners are absent after next-page success/error/abort-by-filter-change, and out-of-order **first-page** responses where an old request resolves last. Add one idle-spinner assertion to the existing `apps/web/e2e/gallery.spec.ts` infinite-scroll test. If they pass on baseline, report the historical spinner as not reproduced rather than forcing a production change.
- `apps/web/src/lib/components/CategoryFilter.svelte` already uses native radios and `chosen`/URL reconciliation; the compact `CategoryBadge` already supplies an `sr-only` category label and this has coverage in `CategoryFilter.svelte.test.ts`. Reveal that **existing label** next to its icon only at a measured wide-header breakpoint; do not duplicate accessible text, change radio state or add dropdown. Keep compact icons, focus/checked styles and touch hit targets.
- `apps/web/src/lib/components/PuzzleCard.svelte` already has the complete `title={family.name}` tooltip on the heading. Replace its one-line `truncate` with `line-clamp-2` at **all** widths; reserve a consistent two-line title block so card rows align. Extend the existing 390×844 status-stack non-overlap test with a long title, checking bookmarks, clear badge and difficulty actions. No modal or new card interaction.
