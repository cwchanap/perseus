## Problem and evidence

These observations describe the pre-change baseline.

1. `apps/web/playwright.config.ts` enables `reuseExistingServer: !process.env.CI` for both Wrangler API (3999, HTTP readiness /api) and Vite preview (4173, TCP readiness). HPA-1028 records ten invalid runs against Gliese, not ten Perseus product failures. Starting a fresh owned server is simpler than identifying a pre-existing build.
2. The preview build and the `API_ORIGIN` constant in `apps/web/e2e/gameplay-fixtures/harness-services.spec.ts` both use `process.env.PUBLIC_API_BASE ?? 'http://localhost:3999'`. Production-mode SvelteKit embeds this value at build time; `apps/web/src/lib/services/api.ts` recommends port 4690 for ordinary local dev. An inherited environment variable can silently send E2E traffic to the wrong API even with server reuse disabled. The existing E2E port is 3999 (`.env.test` agrees); there is no supported remote E2E mode.
3. Stage 4 of `GameplayPage.gotoFixture()` installs the clock at startAt and pauses at that same instant. Time runs between calls, so an already-past target can throw "Cannot fast-forward to the past". Historical 1.64.1 harness-shaped reproduction: 3/3 failures with an injected 150 ms delay; ten isolated serial completion runs passed. This demonstrates the race, not the precise cause of the original contention. `bun.lock` now pins @playwright/test, playwright and playwright-core at 1.65.1; install the lockfile and record the actual version before reproducing.
4. Existing `e2e/playwright-clock-contract.spec.ts` checks performance.now deltas after install/navigation/pause at +5 seconds; it does not exercise the helper's pre-navigation sequence, and its five-second lead is itself vulnerable if navigation stalls. `e2e/gameplay-session-controls.spec.ts` already proves 3 s active + 5 s paused + 2 s resumed = 5 s active, through gotoFixture.

## Decision A — exclusive runner-owned servers and a fixed E2E API origin

Set `reuseExistingServer: false` for both existing entries, in local and CI runs. Use explicit IPv4 loopback endpoints rather than `localhost`: API `url: 'http://127.0.0.1:3999/api'` with a 180 s HTTP readiness budget, Wrangler `--ip 127.0.0.1`, preview `port: 4173` with `--host 127.0.0.1 --strictPort` and its own 180 s startup budget, and baseURL `http://127.0.0.1:4173`. This keeps readiness probes, browser traffic, embedded API traffic, and server binds on one address family instead of depending on platform-specific `localhost` resolution. Preserve build:e2e, the existing dev:e2e migration/auth/CORS setup and test projects. Names may be added for diagnostics, but no orchestration framework.

Rely on Playwright's built-in availability checks plus one narrow preflight for the demonstrated gap. The review inspected the locked runner: `port` entries probe TCP on IPv4 and IPv6, so a foreign TCP listener on 4173 fails before the preview is launched; a ready HTTP service on 127.0.0.1:3999 fails the URL availability pre-check. Playwright cannot combine TCP occupancy with HTTP readiness in one entry (`port` and `url` are mutually exclusive), and HTTP readiness treats only 200-403 as available. A foreign listener already bound to 3999 can therefore escape the initial probe with 503 and then win the startup race by switching to 200 before the Wrangler child exits. To close that demonstrated false pass, `playwright.config.ts` awaits `assertPortFree` from `scripts/assert-port-free.ts` against 127.0.0.1:3999 in the runner process before any `webServer` availability check or process launch; documented Playwright worker environment markers skip the check in workers because workers import config after owned servers are already listening. That point-in-time TCP check is independent of HTTP status and catches listeners already bound when the run starts; it cannot guarantee that no foreign process binds afterward. Retain HTTP readiness, do not switch API readiness to TCP, and do not add a globalSetup probe, server-identity framework, or collision runner. Do not kill foreign processes, hop ports, or add same-checkout reuse protocols. Document stopping the owning process from its own workspace. Concurrent workers within one invocation share the owned services.

Hardcode `http://127.0.0.1:3999` in the preview webServer.env.PUBLIC_API_BASE and the harness-services spec's API_ORIGIN (or share one small E2E constant only if it reduces duplication without adding plumbing). Remove both inherited PUBLIC_API_BASE reads. The explicit env entry must win over process.env; ordinary dev/production build settings remain untouched. Demonstrate with a deliberately inherited local-dev value: run the actual Playwright harness-services spec with PUBLIC_API_BASE=http://localhost:4690, then inspect the client JavaScript in apps/web/build/ generated by that same runner invocation, before any subsequent build overwrites it. Require a nonempty JS set, an embedded http://127.0.0.1:3999 in the client bundle, and no localhost:4690 anywhere in its client JS; record the matching asset path and negative scan result. This checks webServer.env rather than a separately launched preview, and the passing harness-services spec independently exercises its fixed API_ORIGIN. Any existing .env.local stays untouched; the explicit build env must win over it as well. No external service or production endpoint needs to be contacted for this proof.

Record one-time, agent-executed collision checks with temporary listeners on free loopback ports: 4173 with ordinary HTTP (TCP occupancy) and 127.0.0.1:3999 armed to return 503 to a first `/api` request and then 200 during startup (the reproduced foreign-API false pass). Verify nonzero exit, actionable port output, no test bodies run, listener still answers, and owned children exit. No permanent subprocess-based collision suite. Use a listener on the same loopback interface as the intended service so the check exercises the real occupancy path; because the harness pins the API to IPv4 loopback, 127.0.0.1 is the relevant API interface.

## Decision B — pause from an earlier virtual time, before navigation

Keep the existing route/cookie/clock/atomic init/navigation ordering and reduced-motion behavior. Extract the public API calls into a tiny `e2e/support/paused-clock.ts` helper accepting `Pick<Page['clock'], 'install' | 'pauseAt'>`:

```ts
const PAUSE_LEAD_MS = 3_600_000;
await clock.install({ time: new Date(startAt.getTime() - PAUSE_LEAD_MS) });
await clock.pauseAt(startAt);
```

Call from GameplayPage stage 4 on the blank page before app scripts/timers exist. The lead is virtual, not a real wait; it exceeds normal test setup duration. Do not widen timeouts, add retries, use setFixedTime/setSystemTime, or expose delay injection through the product/harness options.

Add one @smoke contract test alongside the existing relative delta test: a small adapter delegates to actual page.clock and inserts a 150 ms host-side wait after install; invoke the actual shared initializer, navigate to '/', assert Date.now() equals the requested startAt. Demonstrate the old sequence fails under that delay (or report accurately if the pinned version differs), and the new helper passes. The existing delta contract and session controls cover elapsed time and pause/resume; keep their assertions unchanged. Correct the misleading numeric-zero baseline claims in gameplay-page.ts, gameplay-infrastructure.spec.ts, and the README. The session-controls header already says performance.now stays frozen; its game-timer-zero wording is not an absolute browser-clock assertion. No extra reload/interval/real-clock suite or ten-repeat stress gate: the injected delay tests this race directly. Retain omitted/false real-clock behavior and existing reduced motion.

References: [Playwright Clock API](https://playwright.dev/docs/api/class-clock), [webServer configuration](https://playwright.dev/docs/test-webserver).
